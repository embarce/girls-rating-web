## 二、功能 A：沉浸式全屏上下刷（ImmersiveFeed）

### 2.1 目标

把「看图」从画廊的扫视改成短视频式的单图沉浸消费：全屏一图、上下滑动切换、双击点赞。用户反馈的直接诉求。

### 2.2 入口

| 入口 | 行为 |
| --- | --- |
| Header 导航新增「沉浸」 | 以当前展区数据（热门/最新）作为初始流进入，从第 1 张开始 |
| Lightbox 顶栏新增 IconButton（从当前作品进入） | 以当前图为起点进入沉浸流（不中断浏览动线） |

### 2.3 数据源（零后端改动）

- 初始流 = 打开时的 `images` 快照（热门 100 张 / 最新当前页）。
- **无限追加**：滚到倒数第 3 张时自动加载——
  - `latest`：沿用 `/api/cosplay?page=n` 顺序追加，直到 `totalPage` 用尽 → 末尾态；
  - `hot`：再拉一次 `/api/random` 追加一批（会话内按 `resourceUrl` 去重，避免同屏重复）。
- 沉浸流内部持有独立 `slides` state，退出不影响画廊分页状态。

### 2.4 交互

| 手势/输入 | 行为 |
| --- | --- |
| 上下滑动 / 滚轮 / ↑ ↓ / Space | 切换上一张 / 下一张（CSS `snap-y snap-mandatory` 原生吸附，不引入虚拟滚动库） |
| **双击图片（移动端 double-tap / 桌面 double-click）** | 点赞 + 心形爆裂动效（未收藏→收藏；已收藏→仅播动效） |
| Esc | 关闭沉浸模式 |
| 底部操作栏 | 收藏 / 下载 / 关闭；左下角常驻展签（作者头像·名字·评分·浏览·rarity 徽章） |

- 右侧进度轨：细竖线 + 当前位圆点 + 「07 / 100」计数（编辑式展签风格，不做短视频的满屏 chrome）。
- 预加载相邻 ±2 张；图片 `object-contain` 于纯黑画布，letterbox 处理竖图/横图。
- 末尾态：最后一张显示「已至末尾 · 返回展区」。
- 性能：`loading="lazy"` + 追加去重；DOM 滑块不回收（数百张量级可接受，万张量级再做窗口化，记为非目标）。

### 2.5 实现要点

- 全屏覆盖层沿用既有模式：`fixed inset-0`、自带顶栏（返回 + 计数 + 关闭）、锁 body 滚动、不走路由。
- **层级：z-[75]**（Lightbox 之上、GachaPage 之下）；从 Lightbox 进入时先关 Lightbox 再开沉浸流（避免双层滚动容器抢滚轮），关闭后回画廊。
- 新组件 `ImmersiveFeed` + `ImmersiveSlide`，加在 `Lightbox` 与 gacha 组件之间；`App` 增加 `isImmersiveOpen` state。
- 新增 keyframes：`heart-burst`；新增 i18n 顶层键 `immersive`（进入/退出/末尾/双击提示/计数模板）。
- 「短视频」指交互形态；本期只有照片，视频素材接入不在范围（R2 支持后另立文档）。

### 2.6 边界

| 场景 | 处理 |
| --- | --- |
| 接口追加失败 | 保留已加载流 + 底部「点击重试」轻提示，不清空 |
| 追加去重后为空（hot 池耗尽） | 直接进末尾态 |
| 图片加载失败 | 该滑块显示展签 + 「加载失败」占位，可跳过 |
| 沉浸中抽卡弹窗触发 | 每日弹窗 z-[110] 正常压上，关闭后回沉浸流 |

## 三、功能 B：卡片预览模式（Lightbox 卡片化）

### 3.1 目标

观展视图里一键把当前照片「变成」它的稀有度卡面：立体 tilt + 全息 foil 即时把玩。既是彩蛋，也是抽卡的转化入口（看中哪张 → 想要它的卡 → 去抽）。

### 3.2 交互

- Lightbox 右侧展签栏操作列表 + 移动端操作栏，各加一个「卡片预览」按钮（`Layers` 图标）。
- 点击后舞台从「原图」切换为 `GachaCard`（大卡、指针 tilt、foil 按照片 rarity 分档），带一次翻面入场动画；再点切回图片态。
- rarity 徽章沿用站内体系：R 灰 / SR 白 / SSR accent 红 + 彩虹 foil。无撒花（非抽取事件，`celebrate=false`）。
- 卡下小字提示：「每日一抽，把这张图收入卡册」+ 按钮 → 关闭 Lightbox 并打开 GachaPage。
- Esc 语义升级：卡片态 Esc 先回图片态，再 Esc 关闭 Lightbox（与 zoomed 同层处理）。

### 3.3 实现要点

- 后端 photo 改造已返回 `rarity`（random / cosplay 均带），前端 `CosplayImage` 接口补声明 `rarity: 'R' | 'SR' | 'SSR'` 即可，**零后端改动**。
- `GachaCard` 组件直接复用（卡面 aspect 固定 3/4，非 3/4 照片 object-cover 裁切，可接受并在 UI 上以「卡面即裁切」暗示）。
- Lightbox 内部加 `cardPreview` state；卡片渲染放舞台中心，尺寸 `min(70vh, 420px)` 宽度约束。
- 无新依赖、无新接口。

## 四、提案池（待拍板）

### C1 收藏夹页（强烈建议）

- **价值**：收藏功能目前只有 toast 反馈，`gr-likes` 存了却没有地方看——这是明显的闭环缺口。
- **方案**：AboutPage 同款全屏覆盖层（z-[70] 同层互斥），瀑布流展示已收藏图（复用 `columnize` + `GalleryCard`），支持在收藏夹内直接取消收藏、点击进 Lightbox；空态引导去画廊收藏。Header 导航加「收藏」（带数量小标）。
- **改动面**：纯前端，~150 行。

### C2 作者专区

- **价值**：作者刚实体化（authors 表 + 头像），但前端只有一行小字。给作者一个落地页，内容组织从「图」升级到「人」。
- **方案**：画廊展签 / Lightbox 作者名可点 → 作者覆盖层（头像 + 名字 + 作品数 + 该作者作品瀑布流）。后端 `/api/cosplay` 增加 `author_id` 过滤参数（repository 一行 where + handler 参数，最小改动）。
- **改动面**：前端 ~180 行 + 后端 ~20 行（含 swagger）。

### C3 卡册图鉴完成度

- **价值**：给卡册加收集元游戏：`status.pool` 已返回全站各档张数，与卡册去重数一比即得完成度。
- **方案**：GachaPage 卡册 tab 顶部加「图鉴 n/m」进度条 + 各档小计（SSR 3/11 …）；集齐一档时徽章点亮。
- **改动面**：纯前端，~60 行。

### C4 分享卡牌图

- **价值**：抽到 SSR 的炫耀回路。Canvas 2D 合成卡面（图 + 稀有度边框 + foil 近似渐变 + 作者展签 + 站点水印）→ PNG 下载 / `navigator.share`。
- **改动面**：纯前端 ~120 行；图片 CORS 已验证可行（下载功能同源逻辑）。

### C5 卡背收集（延后可）

- **价值**：抽卡留存深度：连续抽取天数解锁卡背款式（第 3/7/14 天各一款），GachaCard 卡背组件已参数化成本低。streak 可由卡册 `drawDate` 前端推算。
- **改动面**：纯前端 ~80 行 + 卡背视觉 2–3 款。

### 小彩蛋（顺手项）

- Lightbox 支持快捷键 `?` 呼出快捷键速查；沉浸式内 `L` = 点赞。
